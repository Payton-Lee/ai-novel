## Why

现有小说平台已具备专业工作流和连载记忆，但入口仍以聊天为主。导演的连载准备重新生成大纲并返回手动启动说明，设定与正文分开存储，章节覆盖保存缺少稿件版本，作者难以连续创作和安全修改。

## What Changes

- 以一本书为中心关联设定、已确认大纲、章节、会话和生成任务，建立旧数据兼容映射。
- 接通确认大纲到生成正文的直接操作，避免切换助手和重复填写参数。
- 提供书籍目录、正文编辑区、相关设定与助手侧栏；支持局部修改预览与版本恢复。
- 建立已确认设定、章节版本和记忆快照之间的关系，旧章修改后标记受影响的记忆并阻止无提示地使用旧数据。
- 展示带出处的一致性问题、伏笔状态和可处理建议；读者模拟定位为编辑辅助。
- 提供贯穿全流程的风格配置、生成进度、暂停恢复、用量和预算控制。
- 使用固定十章样本与作者试用验证体验和稳定性，按阶段发布。

## Capabilities

### New Capabilities

以下是首次纳入 OpenSpec 的需求；其中部分后端基础已经存在，不代表全部从零实现。

- `book-workspace`: 书籍身份、设定管理、确认大纲与正文生成闭环。
- `manuscript-revisions`: 正文编辑、局部修改、版本恢复和冲突保护。
- `story-consistency`: 记忆更新、出处可追踪的问题和伏笔管理。
- `generation-control`: 风格、任务生命周期、用量预算和作者体验验证。

### Modified Capabilities

无。仓库尚无既有 OpenSpec 主规格。

## Impact

- 后端：`src/director/`、`src/setting_studio/`、`src/serial_engine/`、`src/novel/` 与相关审稿模块。
- 前端：`web/src/app/`、`components/`、`providers/`；新增书籍 API 与可持久化任务接口。
- 数据：增量增加身份映射、版本、快照、任务和问题记录；迁移前备份，旧数据库不直接覆盖。
- 验证：扩展 pytest，建立前端端到端用例，增加固定十章样本和人工验收记录。
- 范围假设：先服务单人本地中文长篇创作，兼容现有模型配置；首版不做多人协作、支付、自动平台发布或数据库替换。
- 分期与依赖详见 `design.md`、`tasks.md`；四阶段全部完成后才归档本变更。
