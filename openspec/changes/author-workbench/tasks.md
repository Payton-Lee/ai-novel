## 1. P0：基线与书籍数据基础

- [ ] 1.1 记录当前后端测试、前端 lint/build 与两章创作流程基线，交付 `docs/acceptance/author-workbench-baseline.md`，明确既有失败、模型配置和未测项。
- [ ] 1.2 新建书籍服务包与本地 ASGI 入口，更新 Python 依赖和打包配置；通过健康检查及临时数据库 API 测试，验证只绑定回环地址。
- [ ] 1.3 增加 book、旧身份映射、设定与大纲版本表及迁移编号；用两个同名故事验证不会误合并且跨书读取隔离。
- [ ] 1.4 实现旧库迁移预览、一致性备份、显式关联和幂等导入；测试重复导入、歧义和中途失败，校验章节数与正文内容并演练备份恢复。
- [ ] 1.5 增加章节追加版本、当前版本指针和 revision 条件写入；测试旧版本提交被拒绝且已有正文不丢失，为 P0 编辑提供最低保护。
- [ ] 1.6 增加 Next.js 书籍 API 代理与统一启动、健康检查脚本；验证书籍与现有 LangGraph 会话路由均可访问且浏览器响应不包含密钥。

## 2. P0：从确认大纲到正文

- [ ] 2.1 实现设定草案、确认与锁定接口；测试 AI 提议不能覆盖锁定内容，作者操作生成新的设定版本。
- [ ] 2.2 将已有大纲转为可确认的分卷章节结构并保存目标字数；用格式异常输入验证错误可见且不会静默替换大纲。
- [ ] 2.3 修改导演连载准备，直接创建使用已确认大纲、设定版本的任务；通过模型替身捕获输入，确认没有调用重新规划路径。
- [ ] 2.4 实现最小持久任务记录和单章执行、结果候选版本；测试重复点击只生成一个逻辑任务，启动后修改大纲不改变其快照。
- [ ] 2.5 实现书籍列表与目录、正文编辑区、设定/助手侧栏；通过浏览器验证重新打开书籍仍显示保存内容，不需要助手 ID 或参数输入。
- [ ] 2.6 接入手动保存、明确保存状态、采用生成稿与继续下一章；模拟网络失败验证编辑内容保留且没有误报保存成功。
- [ ] 2.7 为现有导出脚本增加书籍当前选定版本入口并接入界面；比较导出正文和章节顺序，确认不会导出已拒绝候选稿。
- [ ] 2.8 配置 Playwright 脚本和确定性后端夹具，验证创建书籍、确认大纲、生成第一章、手改、保存、续写第二章和导出；记录 P0 演示结果后再进入 P1。

## 3. P1：安全修改与可靠恢复

- [ ] 3.1 实现版本列表、差异比较与恢复接口和界面；测试从第三版恢复第一版会产生第四版，第二版和第三版仍可读取。
- [ ] 3.2 接入选区重写，保存基准版本和选区校验；验证采用只改变选区，拒绝不写正文或记忆，过期建议不可直接应用。
- [ ] 3.3 增加自动保存及双页面冲突处理；端到端验证甲保存后乙的旧写入不会覆盖，并可保留乙的未提交内容。
- [ ] 3.4 扩展任务队列状态、心跳和阶段检查点；注入提交前后崩溃，验证重启后可恢复且不重复提交已完成章节。
- [ ] 3.5 实现暂停、取消、重试和书籍级串行执行；测试暂停后的下一安全边界不再发起模型调用，同时展示在途调用状态。
- [ ] 3.6 展示章节/阶段进度、错误和继续入口；模拟十章任务在第四章失败并重启服务，验证前三章版本不变且从未完成工作继续。
- [ ] 3.7 执行 P1 跨模块回归及迁移回滚演练，交付验收记录；恢复稿件逐字相同、无重复提交和无新增丢稿问题才进入 P2。

## 4. P2：长篇一致性与写作控制

- [ ] 4.1 为记忆快照和摘要绑定正文、设定版本，实现修改旧章后保守失效；测试第三章修改会标记相关后续记忆过期且后续正文不被改写。
- [ ] 4.2 实现队列化记忆重建与有效快照事务切换；注入失败验证不会发布半成品记忆，续写被阻止直到重建成功，且只使用当前章以前事实。
- [ ] 4.3 将一致性检查结果结构化为版本、原文位置、证据、确定性等级和处理状态；用人物提前知情样本验证依据可回溯。
- [ ] 4.4 实现问题侧栏及查看、局部修订、设定提议和忽略操作；验证旧版本问题标记过期，锁定设定仍需作者显式处理。
- [ ] 4.5 实现伏笔埋设、推进、回收出处与手动修正；测试确认回收后不再报未回收，无出处的提取仅呈现为建议。
- [ ] 4.6 统一书籍风格和章节覆盖配置，贯穿创意、大纲、正文、审稿及辅助生成器；捕获慢热悬疑模式各阶段输入，验证没有冲突的强制番茄指令。
- [ ] 4.7 调整读者模拟的输出结构和 UI 文案，展示段落依据并区分模型建议与真实反馈；测试不出现真实留存率保证或无依据评分解释。
- [ ] 4.8 执行“修改第三章→重建→续写”集成场景及 P2 演示；检查新任务引用有效快照、问题定位正确、前两阶段功能无新增回归。

## 5. P3：资源预算与作者验收

- [ ] 5.1 汇总各模型调用的 token、重试、价格来源与估算费用；使用有/无 usage 和有/无价格四类替身验证未知值不记为零。
- [ ] 5.2 增加调用/token 上限与可选货币预算，调用前预留、调用后结算；测试超过额度自动暂停、调整后继续且重试计入额度。
- [ ] 5.3 在任务详情显示进度、用量、重试和预算暂停原因；浏览器测试价格缺失时货币上限不可启用且仍可用调用次数限制。
- [ ] 5.4 扩展压力测试为固定十章夹具，覆盖人物秘密、年龄约束、三条伏笔与故障；交付可重复命令和机器可读报告，区分模型替身与真实模型结果。
- [ ] 5.5 对同一夹具运行真实模型并记录模型、参数、提示词版本、费用和人工判断；与基线比较大纲偏离和一致性问题，不把自评分当成真实质量收益。
- [ ] 5.6 完成至少三位目标作者各两章的试用记录，统计闭环完成、首章耗时、改稿时间与建议采纳；至少两位独立完成，无参与者时此项保持未完成。
- [ ] 5.7 更新 README、CLAUDE.md 和用户操作文档，移除与实现不符的模板描述；由验收者按文档完成启动、创作、恢复、导出流程。
- [ ] 5.8 执行受影响 pytest、Ruff/mypy、前端 lint/format/build、Playwright 和 OpenSpec 严格校验，汇总已知限制及四阶段证据；所有需求验收后再同步主规格并归档。
